# Лабораторна робота №9

## Тема: Автентифікація та авторизація у Spring Boot з використанням Spring Security

---

##  1. Мета роботи
Ознайомитися з механізмами автентифікації та авторизації у Spring Boot на основі фреймворку **Spring Security**.
Навчитися конфігурувати захист HTTP-маршрутів, працювати з користувацькими акаунтами,
реалізовувати обмеження доступу на основі ролей, а також створювати власну реалізацію
`UserDetailsService` для завантаження користувачів із бази даних.

Закріпити навички побудови веб-застосунків із розмежуванням прав доступу
та безпечною обробкою даних.

---

##  2. Принципи автентифікації та авторизації

### Автентифікація
У проєкті реалізована через форму логіну.
Облікові дані (email та пароль) перевіряються шляхом порівняння
введеного пароля з **хешованим значенням** у базі даних.

### Авторизація
Реалізована на основі ролей **USER** та **ADMIN**.
Система перевіряє права користувача перед наданням доступу
до конкретних URL-адрес або методів.

---

##  3. Опис реалізації

### Модель користувача
У модулі **core** розширено доменну модель `User`:
- `email`
- `nickname`
- `role`
- статус верифікації акаунта

### UserDetailsService
Створено клас **AppUserDetailsService**, який:
- завантажує користувача з БД за `email`
- перетворює його на об'єкт, сумісний зі Spring Security

### SecurityConfig
Налаштовано ланцюжок фільтрів безпеки:
- публічні маршрути (`permitAll`)
- маршрути з обмеженням доступу (`hasRole`)

### Хешування паролів
Для безпечного зберігання паролів використовується
**BCryptPasswordEncoder**.

##  5. Відповіді на теоретичні питання

### Як реалізована автентифікація?
Spring Security використовує `AppUserDetailsService`
для завантаження користувача за email.
Перевірка пароля виконується автоматично через
`DaoAuthenticationProvider` з використанням `BCryptPasswordEncoder`.

### Як реалізовано авторизацію?
Авторизація налаштована в `SecurityConfig` через `requestMatchers`.
На рівні UI використано `sec:authorize`
для приховування або відображення елементів.

### Поведінка неавторизованого користувача
- Неавтентифікований користувач:
  - `/login` (web)
  - `401 Unauthorized` (API)
- Недостатні права:
  - `403 Forbidden`
  - кастомна сторінка помилки

##  6. Висновки

Поділ доступу за ролями дозволив мінімізувати ризики
несанкціонованої зміни даних та чітко розмежувати функціонал.

Власна реалізація `UserDetailsService` забезпечила
інтеграцію Spring Security з реальною бізнес-логікою та БД.

Spring Security надав готовий та надійний захист
від типових вразливостей та централізоване керування
політикою безпеки.

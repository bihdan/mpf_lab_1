#  MPF Labs: 3-Tier Web Application

Багатомодульний Maven-проєкт, що реалізує **каталог книг із відгуками**, побудований на принципах **трирівневої архітектури**.

---

## Архітектура проєкту

Проєкт розділений на **три логічні модулі** з чітким спрямуванням залежностей:

### 🔹 core
- Доменні моделі: `Book`, `Comment`
- Класи пагінації
- Порти (інтерфейси) репозиторіїв  
- Бізнес-логіка:
  - правило **видалення відгуків лише протягом 24 годин**

### 🔹 persistence
- Реалізація доступу до даних через **JDBC**
- Використання **H2 Database**
- Створення схем БД
- Виконання SQL-запитів

### 🔹 web
- HTTP-інтерфейс на базі **Servlet API**
- Рендеринг **JSP**
- Обробка параметрів запиту
- Повернення помилок у **JSON-форматі**

- **WARN** — клієнтські помилки (наприклад, `409 Conflict`)

##  Відповіді на контрольні питання

### 1. Які переваги дає використання трирівневої архітектури?

- **Розділення відповідальності** — кожен шар виконує свою роль
- **Гнучкість** — можна змінити БД без переписування веб-інтерфейсу
- **Масштабованість** — кожен рівень розвивається незалежно

---

### 2. Чому доменний шар (`core`) не повинен залежати від JDBC чи Servlet API?

- Забезпечується **незалежність бізнес-логіки від технологій**
- Доменні моделі можна:
  - легко тестувати
  - повторно використовувати
  - переносити в інші типи застосунків

---

### 3. Як ArchUnit допомагає підтримувати архітектурну дисципліну?

- Перетворює архітектурні правила на **unit-тести**
- Не дозволяє зібрати проєкт при порушенні залежностей
- Захищає від випадкових помилок (наприклад, залежності `core → web`)

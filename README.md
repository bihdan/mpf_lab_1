# Лабораторна робота №4  
## Spring MVC

---

## 🎯 Мета роботи

Ознайомитися з архітектурою **Spring MVC** та механізмом маршрутизації через `DispatcherServlet`.

Перевести веб-застосунок з архітектури сервлетів на **Spring MVC контролери**.

Навчитися організовувати обробку HTTP-запитів, передачу даних між шарами застосунку та формування **JSON-відповідей**.

---

## 🏗️ Архітектура застосунку

Проєкт реалізовано з використанням **Spring Boot** та розділено на три модулі:

- **Core**  
  Містить доменні моделі (`Book`, `Comment`) та сервіси з бізнес-логікою.

- **Persistence**  
  Реалізує порти доступу до даних через **JDBC** та базу даних **H2**.

- **Web**  
  Містить Spring MVC-контролери, конфігурацію `WebConfig` з анотацією `@EnableWebMvc` та систему глобальної обробки помилок.

---

## 📖 Теоретичні відомості

### Ролі основних компонентів

**DispatcherServlet**  
Виступає як *Front Controller*. Це центральна точка входу, яка приймає всі HTTP-запити та перенаправляє їх до відповідних контролерів.

**Контролери (`@Controller` / `@RestController`)**  
Класи, що містять логіку обробки конкретних URL-адрес.  
Вони:
- приймають вхідні дані;
- викликають бізнес-логіку;
- повертають відповідь клієнту.

**Моделі**  
Об'єкти (`Book`, `Comment`), які переносять дані між базою даних, бізнес-логікою та клієнтом.

---

### Spring MVC vs Servlets

На відміну від сервлетного підходу, де необхідно вручну:
- парсити параметри запиту;
- обробляти типи контенту;
- формувати відповіді,

**Spring MVC** пропонує декларативний підхід на основі анотацій.  
Це автоматизує:
- маршрутизацію;
- серіалізацію JSON;
- валідацію даних;

та робить код значно чистішим і читабельнішим.

## ❓ Відповіді на питання

### 1. Яку роль у Spring MVC виконує `DispatcherServlet`?

`DispatcherServlet` координує весь процес обробки запиту:
- приймає HTTP-запит;
- звертається до `HandlerMapping`;
- викликає відповідний контролер;
- повертає результат клієнту.

---

### 2. Чим відрізняються анотації `@Controller` і `@RestController`?

- `@Controller` використовується для повернення **View** (наприклад, JSP).
- `@RestController` автоматично додає `@ResponseBody` до кожного методу та повертає дані у форматі **JSON**.

---

### 3. Як у Spring MVC організована маршрутизація HTTP-запитів?

Маршрутизація здійснюється через анотації:
- `@RequestMapping`
- `@GetMapping`
- `@PostMapping`

Spring сканує ці анотації під час запуску та будує карту маршрутів.

---

### 4. Як у контролері отримати параметри з рядка запиту (`page`, `size`, `q`)?

За допомогою анотації `@RequestParam`.

```java
public List<Book> search(@RequestParam String q)
```

### 5. У чому різниця між `return "books"` і `return ResponseEntity.ok(books)`?

- `return "books"` змушує Spring шукати представлення з назвою **`books`**  
  (наприклад, файл `books.jsp`) і рендерити HTML-сторінку.

- `return ResponseEntity.ok(books)` повертає самі дані об’єкта **`books`**  
  у форматі **JSON** разом з HTTP-статусом **200 OK**.

---

### 6. Яким чином контролер передає запит до бізнес-логіки у Spring MVC?

Контролер викликає методи сервісних класів з модуля **core**, які впроваджуються
в нього через **ін’єкцію залежностей (Dependency Injection)**, зазвичай
через **конструктор**.

---

### 7. Як отримати ідентифікатор книги з URL `/books/{id}`?

Для отримання ідентифікатора з URL використовується анотація `@PathVariable`:

```java
@GetMapping("/{id}")
public Book get(@PathVariable long id) {
    return bookService.getById(id);
}
```

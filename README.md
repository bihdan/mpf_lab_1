# Лабораторна робота №6  
## Тема: Шаблонізація у Spring MVC з використанням Thymeleaf

---

## 🎯 1. Мета роботи

Ознайомитися з принципами серверного рендерингу у Spring MVC.  
Навчитися створювати динамічні сторінки, реалізовувати **form binding**, використовувати **фрагменти** та забезпечувати **багатомовність (локалізацію)** інтерфейсу.

---

## 📖 2. Теоретичні відомості

**Thymeleaf** — це сучасний серверний шаблонізатор Java, який тісно інтегрується зі Spring MVC.  
Його головна особливість — концепція **Natural Templates**: HTML-файли залишаються валідними документами, які можна відкрити у браузері як статичні макети, а атрибути `th:*` обробляються сервером під час запиту.

### 🔑 Ключові переваги Thymeleaf

- **Natural Templates** — можливість верстки без запуску сервера  
- **Form Binding** — автоматичне відображення даних об'єкта у форму та зчитування результатів  
- **i18n** — вбудована підтримка ресурсних файлів для локалізації  
- **Фрагменти** — повторне використання частин інтерфейсу (DRY — *Don't Repeat Yourself*)

---

## 🏗️ 3. Структура реалізованого застосунку

Застосунок побудований на базі **модульної структури**.  
Основна логіка рендерингу зосереджена в модулі **web**.

### Основні компоненти:

- **Контролери**  
  `BooksController` обробляє HTTP-запити, взаємодіє з сервісами  
  (`CatalogRepositoryPort`, `CommentRepositoryPort`) та додає дані в  
  `org.springframework.ui.Model`.

- **Глобальна конфігурація**  
  Реалізовано клас `GlobalControllerAdvice` для автоматичного додавання  
  об'єкта `urlBuilder` у всі шаблони. Це дозволяє коректно змінювати мову  
  зі збереженням параметрів URL.

- **Шаблони**  
  Розташовані у `src/main/resources/templates/`.

- **Локалізація**  
  Використовуються файли:
  - `messages.properties` (UA)
  - `messages_en.properties` (EN)
  - `messages_fr.properties` (FR)

## ❓ 5. Відповіді на теоретичні питання

### 1. Які принципи роботи серверного рендерингу в Spring MVC та яку роль відіграє Thymeleaf?

При серверному рендерингу (SSR) HTML-код сторінки повністю формується на боці сервера.  
Spring MVC отримує запит, контролер готує дані (**Model**) і повертає ім'я представлення.  
**Thymeleaf** виконує роль View Engine: бере HTML-шаблон, підставляє дані з моделі за допомогою атрибутів `th:*` та надсилає готову сторінку у браузер.

---

### 2. Як у Thymeleaf організована локалізація інтерфейсу (i18n)?

Локалізація базується на ресурсних файлах `.properties`.  
У шаблонах використовуються ключі замість тексту:

```html
<span th:text="#{label.title}"></span>
```

Spring автоматично обирає відповідний файл локалізації на основі
`LocaleResolver`.

Для зручного перемикання мов у застосунку реалізовано динамічну побудову
посилань через `ServletUriComponentsBuilder`, що дозволяє зберігати
параметри поточного URL.

---

### 3. Що таке фрагменти (layout) у Thymeleaf та як вони допомагають?

Фрагменти — це частини HTML-коду, позначені атрибутом `th:fragment`.

Вони дозволяють повторно використовувати однакові блоки інтерфейсу
(наприклад, **header** або **footer**) на різних сторінках
за допомогою `th:replace`.

Це значно спрощує підтримку коду, оскільки:
зміни у файлі `header.html` автоматично відображаються
на всіх сторінках застосунку.

## ✅ 7. Висновки

В ході лабораторної роботи було реалізовано повноцінний **MVC-інтерфейс**.
Використання **Thymeleaf** дозволило ефективно розділити логіку
(контролери) та представлення (HTML).

### Ключові досягнення:

- Реалізовано **form binding**, що спростило передачу даних
  від користувача до backend-моделі
- Впроваджено систему **i18n** для трьох мов
- Вирішено проблему втрати параметрів URL при зміні мови
  за допомогою `@ControllerAdvice`, що підвищило
  зручність користування інтерфейсом (UX)
